# Artifact Management

Follow these instructions to maintain consistency across all SDLC artifacts generated by the workflow:

## 1. Directory Structure
Align files strictly to their designated folders under `sdlc-artifacts/`:
- `01-budget-pitch/` — Output of PO Ideation. Contains an `input/` subfolder (`sdlc-artifacts/01-budget-pitch/input/`) for starting materials (client interviews, demands, product briefs).
- `02-business-requirements/` — Output of PO Discovery
- `03-it-specification/` — Output of RE Requirement Analysis
- `04-story-map/` — Output of RE Story Mapping
- `05-elaborated-stories/` — Output of RE Elaboration (one file per story)
- `06-design/` — Output of Architect Design (one file per story)
- `07-implementation-plan/` — Output of Developer Plan (one file per story)
- `09-test-cases/` — Output of Test Analyst (one file per story)
- `workflow-status.md` — Central tracker of the SDLC pipeline progress and resume instructions

## 2. Naming Conventions
- **Initiative-Level Documents** (pitch, business requirements, IT spec, story map):
  - Path: `sdlc-artifacts/<phase-folder>/<initiative-slug>.md`
  - Example: `sdlc-artifacts/02-business-requirements/payment-gateway.md`
- **Per-Story Documents** (elaboration, design, implementation plan, test cases):
  - Path: `sdlc-artifacts/<phase-folder>/<initiative-slug>__<story-id>.md`
  - Example: `sdlc-artifacts/05-elaborated-stories/payment-gateway__story-101.md`

## 3. Context Discipline
- Read **only** the specific artifact file(s) referenced by path or ID in the prompt. Do not perform broad directory listings or search across all artifact folders unless explicitly requested.
- If the target artifact is missing or the user's prompt is ambiguous, stop and ask the user for the specific path or ID before proceeding.
- Write outputs exactly to the mapped folder. Never modify earlier-stage artifacts.
